# 03: Mechanical Grounding and Hallucination Elimination

## 1. Zero-Tolerance Hallucination Policy
Given the critical nature of underwriting risk assessments, the system operates under a strict "no hallucinations" mandate. This is not managed by prompting ("please do not hallucinate"); it is enforced mechanically at the architectural layer.

## 2. Evidence-Binding Protocol
Every factual claim, numerical extraction, or analytical assertion generated by an LLM-powered agent must carry a resolvable citation.

### Citation Sources
1. **Document Spans:** Bounding box coordinates and page numbers from Document AI.
2. **Enrichment Responses:** JSON object paths from Apigee API payloads.
3. **Rule Traces:** `Rule_IDs` from the Symbolic Rating Engine.

## 3. Enforcement Mechanisms
* **Agent Outputs:** Agents are required (via ADK system instructions and structured output schemas) to return responses containing both `claim_text` and `citation_uri`.
* **The Grounding Gateway:** An intermediate validation service intercepts agent outputs before they reach the shared memory layer or the A2UI frontend.
    * It parses the `citation_uri`.
    * It verifies the URI exists in the session's source material.
    * **Block Action:** Uncited claims or invalid URIs are completely blocked and purged from the response, triggering an agent retry or flagging a system error.

## 4. CI/CD Groundedness Gates
During the testing phase, the system runs a suite of LLM-as-a-Judge evaluators. 
* The pipeline will fail (gate) if the groundedness evaluator detects any uncited claims in the test scenarios.
* **Target Metric:** 0% ungrounded assertions.

## 5. Regulator-Ready Audit Pack
The system compiles a continuous audit log. When an underwriter clicks "Export Audit" on a quote, the system produces a package containing:
* The original submitted PDF.
* The Doc AI extraction mapping.
* The external API payloads used.
* The exact version of the Symbolic Rules Engine executed.
* The deterministic trace of applied rule IDs.
